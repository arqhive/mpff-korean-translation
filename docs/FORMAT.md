# 메트로이드 프라임 페더레이션 포스 — 파일 구조 정리

일본판(CTR-P-BCAJ, 타이틀 ID `000400000016CE00`) 기준. 전부 실측으로 확인한 것이고,
틀린 가정 때문에 겪은 실패도 같이 적어 둔다.

## 왜 일본판인가

- 언어 슬롯이 하나뿐이다. 북미판은 `init.efigs` 한 파일에 영어·프랑스어·이탈리아어·독일어·
  스페인어가 같이 들어 있어서, 한 언어만 한글로 바꾸면 나머지 언어 칸이 깨진다.
- 폰트 아틀라스가 19페이지다. CJK를 담기 위한 크기라 한글에 그대로 쓸 수 있다.
  북미판 아틀라스는 라틴 문자용이라 한글 1,000자 이상이 들어갈 자리가 없다.
- 루비(후리가나) 글리프를 빼면 자리가 더 생긴다.

## 텍스트는 전부 한 파일에 있다

`romfs/init.jp` 하나에 게임 내 모든 문자열 2,119개가 들어 있다. 대사·브리핑·메뉴·HUD·
칩 설명·데이터뱅크 로그·시스템 메시지까지 전부다. 다른 pak 에는 문자열 테이블이 없다.

확인 방법: 모든 `.jp` pak 의 섹션 0(리소스 인덱스)에서 문자열 테이블 태그
`0x42027020` 를 찾아봤고, init.jp 에만 있었다.

## NLG pak 컨테이너

한 pak 은 세 파일로 나뉜다.

| 파일 | 내용 |
|---|---|
| `<이름>.data` | 언어와 무관한 공용 청크 |
| `<이름>.dict` | 청크 표 (어느 파일 어디에 무엇이 있는지) |
| `<이름>.<언어>` | 언어별 청크 (`.jp`, `.efigs`) |

`.jp` 본문은 zlib(level 6) 스트림을 이어 붙인 것이다. 각 스트림은 8바이트 경계에서
시작하고 남는 자리는 `0x00` 으로 채운다. `0x78` 로 시작하지 않으면 비압축이다.

### 섹션 0 = 리소스 인덱스

12바이트 레코드가 이어진다.

```
u32 typeTag      상위 니블에 섹션 번호가 섞여 있다
u32 size
u32 offset       ★ 섹션별 오프셋이다 (파일 전체 기준이 아니다)
```

주요 태그:

| 태그 | 내용 |
|---|---|
| `0x42027020` | 문자열 테이블 (섹션 2) |
| `0x33027011` | 폰트 정의 (섹션 1) |
| `0x33027012` | 폰트 페이지 목록 (섹션 1) |
| `0x5701B502` | 폰트 페이지 비트맵 (섹션 3) |
| `0xE977D350` | 텍스처 기술자 (섹션 1 앞머리, 56바이트 간격) |

### `.dict` = 청크 표 — **빼먹으면 텍스트가 전부 사라진다**

```
magic 0xA9F32458
u32   version
u32   최대 압축 크기
u32   266802 (전역 상수)
16바이트 이름 엔트리들
16바이트 청크 엔트리들 { compOffset, rawSize, compSize, flags }
                        flags 비트16~23 = 확장자 인덱스
확장자 문자열  ".efigs\0.debug\0.jp\0.data\0"
```

`init.jp` 를 새로 만들면 `.dict` 의 `.jp` 엔트리 4개와 헤더 `0x08`(최대 압축 크기)을
반드시 갱신해야 한다. 이걸 빼먹어서 게임 내 모든 텍스트가 빈칸으로 나오는 문제를
세 번 겪었다.

## 문자열 테이블

```
u32 languageIndex     JP = 1
u32 count             2119
count × { u32 nameHash, u32 charOffset }    charOffset 단위는 UTF-16 코드 유닛
UTF-16LE 문자열들 (NUL 종료)
```

- 중복 제거를 하지 않는다. 같은 문자열이 두 번 나오면 두 번 써야 한다.
- 블롭에 놓인 순서가 엔트리 순서와 다르다. **원본 블롭 순서를 지켜야 한다.**
- 해시는 오름차순이다.

### 텍스트 태그

| 태그 | 뜻 |
|---|---|
| `{p}` | 줄바꿈 |
| `{vs:n}` | 행간 |
| `{tp:n}` | 글자 출력 속도 |
| `{ts:n}` | 글자 크기 배율 |
| `{clr:RRGGBB}` | 색 (키워드 강조는 `FF9F00`, 경고는 `FF0000`) |
| `{rb}` `{rt}` | 루비(후리가나). 일본판 전용이라 한글판에는 쓰지 않는다 |

태그가 깨지면 그 문자열이 통째로 화면에 안 나온다.

## 폰트

### 정의 파일

`NLG Font Description File` 로 시작하는 평문이다. **줄바꿈이 CRLF 이고 꼬리 공백까지
의미가 있다.** LF 로 바꿔 썼다가 텍스트가 전부 사라진 적이 있다.

```
Glyph <문자 또는 10진 코드포인트> Width a b c d
```

- `a` = 送り폭(advance)
- `b` = 아틀라스에서 차지하는 칸 폭
- `c`, `d` = 그리는 위치 보정

글리프는 정의에 적힌 순서(= 코드포인트 오름차순)대로 아틀라스에 채워진다.
페이지는 256×256, 행 높이 34px, 한 페이지에 7행이다.

### 정의가 5벌 있다

| # | 이름 | 글리프 | 페이지 | 비고 |
|---|---|---|---|---|
| 0 | DFGothicP-W5 | 1130 | 19 | 메인 |
| 1 | DFGothicP-W5-Blur | 12 | 1 | 숫자·`:`·`?` |
| 2 | DFGothicP-W5 | 1130 | 19 | **메인과 같은 내용. 둘 다 고쳐야 한다** |
| 3 | Digitneil | 11 | 1 | 숫자 |
| 4 | DFGothicP-W5_ruby | 91 | 2 | 루비 전용 가나. 한글판에서는 미사용 |

0번만 고치면 특정 화면에서 글자가 깨진다. 0번과 2번을 함께 고쳐야 한다.

### 아틀라스 페이지 포맷 — **페이지 0~2 는 ETC1A4 다**

| 크기 | 포맷 |
|---|---|
| 43,680 | 256² 4bpp, 밉 6단 |
| 87,296 | 256² **ETC1A4** 8bpp, 밉 5단 |
| 10,912 | 128² 4bpp |
| 5,376 | 64² ETC1A4 |

처음에는 87,296바이트를 IA4(인텐시티+알파)로 잘못 봤다. 니블을 나눠 봐도 화면이
체커보드처럼 깨져서, 결국 ETC1A4 임을 알아냈다.

ETC1A4 는 8×8 타일을 4×4 블록 4개로 나누고, 블록마다 **알파 4bpp 8바이트 + ETC1 색
8바이트** 를 둔다. 블록 순서는 모턴, 블록 안은 열 우선이다. 알파 평면만 뽑으면
글리프 모양이 정확히 나온다(`scripts/etc1a4.py`).

ETC1 색을 다시 인코딩하는 건 만들지 않았다. 대신 **0~2페이지를 고정**하고 한글을
3페이지부터 채운다. 그 위에 있던 글리프 112자(버튼 아이콘 등)는 원래 자리에 그대로
남는다. 남는 자리는 16페이지이고, 한글 1,308자까지 들어간다(현재 775자 사용).

4bpp 페이지는 3DS 표준 8×8 모턴 타일이고 세로로 뒤집혀 있다.

### 밉맵은 건드리지 않은 페이지에 손대지 마라

자리가 바뀌지 않은 페이지의 밉맵을 다시 만들었다가, 작은 글자(ⓒ2016 Nintendo 등)가
무지개색으로 깨지고 일부 가나가 사라졌다. 원본과 밉 필터가 다르기 때문이다.
**글리프 배치가 바뀐 페이지만 다시 인코딩한다.**

### 한글 메트릭

Pretendard SemiBold 24pt, 칸 폭 `b = 22`, advance `a = 22`.
모든 음절을 같은 펜 원점(`x=1`, `baseline y=24`, PIL `anchor="ls"`)에 그려야 한다.
글자마다 잉크 경계에 맞춰 그렸더니 기준선이 들쭉날쭉해졌다.

공백은 원본 advance 가 4px 인데, 한글 사이 1px 간격과 구분이 안 돼서 7px 로 넓혔다.

## 섹션 3 크기 한계 — 989,952바이트

넘기면 부팅 중 크래시한다. 어설션 PC `0x003CA7F4`, LR `0x002DA72C`, R5 레지스터에
섹션 3 크기가 그대로 들어 있어서 알아냈다. 페이지를 늘리려는 시도는 전부 여기서 막혔다.

## 화면에 들어가는 글자 수

상자 폭을 일본어 원문으로 가늠하면 안 된다. 일본어 문장이 원래 짧아서
`{vs:16}{tp:0.07}` 상자의 일본어 최대 줄 폭은 451px 인데, **같은 상자에 북미판은
1,023px 짜리 줄을 싣는다**(`"First, we'll position a special drill specifically"`).
상자는 넉넉하다. 한글 최대는 449px 이다.

## 배너와 아이콘 (ExeFS)

게임 밖 HOME 메뉴에 나오는 것들이다. romfs 가 아니라 ExeFS 에 있다.

### icon.bin = SMDH

```
magic "SMDH", u16 version, u16 reserved
16 × { short[0x40], long[0x80], publisher[0x40] }   전부 UTF-16LE, 0x200바이트씩
```

언어 순서는 일본어, 영어, 프랑스어, 독일어, 이탈리아어, 스페인어, 중국어간체,
**한국어(7번)**, 네덜란드어, 포르투갈어, 러시아어, 중국어번체다. 원본은 0·1번만 채워져
있다. 본체 언어와 무관하게 한글로 보이도록 12칸 전부에 한국어 제목을 넣었다.

48×48·24×24 아이콘은 RGB565 모턴 타일이고, 연방 엠블럼이라 글자가 없다.

업데이트 타이틀(`0004000E0016CE00`)도 자체 `icon.bin` 을 갖고 있어서(내용은 같은 일본어,
md5 는 다름) HOME 메뉴 제목이 그쪽으로 덮일까 걱정했는데, **실기에서 확인한 결과 덮이지
않는다.** 업데이트를 설치해도 본편의 한국어 제목과 아이콘이 그대로 나온다. 따라서
업데이트 CIA 는 건드릴 필요가 없다. 업데이트에는 `banner.bin` 도 없어서 배너 역시
본편 것이 쓰인다.

### banner.bin = CBMD

```
0x00 magic "CBMD"
0x08 공용 CGFX 오프셋 (= 0x88)
0x0C~ 언어별 CGFX 오프셋 (이 게임은 전부 0 = 공용 하나만 쓴다)
0x84 CWAV 오프셋
```

`0x88` 의 CGFX 는 **LZ11 로 압축돼 있다**(`scripts/lz11.py`). 풀면 텍스처 4장이 나온다.

| 이름 | 크기 | 내용 | 조치 |
|---|---|---|---|
| COMMON3 | 256×64 | "FEDERATION FORCE" 로고 | 일본판도 영문. 그대로 |
| COMMON4 | 128×128 | 연방 엠블럼 | 글자 없음 |
| COMMON5 | 256×64 | "METROID PRIME" 로고 | 일본판도 영문. 그대로 |
| COMMON6 | 256×16 | 「メトロイドプライム フェデレーションフォース」 | **한글로 교체** |

전부 RGBA8(바이트 순서 A,B,G,R) 모턴 타일이다. **세로로 뒤집혀 있지 않다** —
폰트 아틀라스(4bpp 페이지)는 뒤집혀 있어서 그 관례를 그대로 옮겼다가 실기에서 배너
글자가 거꾸로 나왔다. 인코더가 디코더의 역함수이기만 하면 왕복 검사는 통과하므로
이 실수는 왕복으로 잡히지 않는다. 뒤집지 않고 디코딩해 글자가 똑바로 서는지
눈으로 확인해야 한다.

텍스처 데이터 오프셋은 TXOB 헤더의 `dataOffset` **필드 위치 기준 상대값**이다.

COMMON6 는 흰 글자 코어에 시안(`#03CCEB`) 글로우가 깔린 구조다. 같은 방식으로 다시
그렸다(`scripts/make_banner_strip.py`).

ExeFS 를 다시 쓸 때는 헤더의 오프셋·크기와 파일별 SHA-256 을 다시 계산해야 한다.
`.code` 는 ExeFS 안에서 압축돼 있으므로 원본 블롭을 그대로 옮긴다.

## 게임 안 그래픽에는 일본어가 없다

`.jp`(언어 전용) 파일 중 텍스처를 가진 것은 `init.jp` 하나뿐이고, 그 안의 비폰트
텍스처 4장은 전부 폰트였다(숫자 폰트 2종, 루비용 가나 폰트). 나머지 텍스처는 모두
`.data`(언어 공용)에 있어서 북미판과 같은 바이트다. 즉 일본어가 들어갈 수 없다.

`credits.txt` / `creditsbb.txt` 도 영문 스태프 이름뿐이다.

## CXI 재빌드

```
3dstool -cvtf romfs romfs.bin --romfs-dir rx
3dstool -cvtf cxi ff.cxi --header cxi/ncchheader.bin --exh cxi/exheader.bin \
        --logo cxi/logo.bin --plain cxi/plain.bin --exefs cxi/exefs.bin \
        --romfs romfs.bin --not-encrypt
```

romfs 를 다시 빌드하면 파일 배치가 원본과 달라진다. 1.2GB 중 98.4%가 바뀌므로
**원본 CIA 에 xdelta/bps 를 뜨는 방식은 쓸 수 없다.** 그래서 배포는 LayeredFS 로 한다.
